# swift-client v0.1.0-beta.4 (pre-release)

> Pre-release page: https://github.com/zht7063/portable-agent-client/releases/tag/v0.1.0-beta.4
> The build commit, SHA-256 values and workflow run are recorded in the GitHub release body once it is published.

## English

**This is a pre-release (beta) for testing. Do not rely on it for production work.**

### What's new since v0.1.0-beta.3

- **HTTPS server (#11):** the fixed build-time origin is now `https://flowpier.top` (no port). The D-17 cleartext-HTTP
  exception that applied to beta.3 has ended. The official build guard accepts only bare `https:` origins again and
  rejects `http:`, `.invalid` placeholders, paths, userinfo, an explicit default port, trailing-dot hosts and (official
  builds) loopback hosts. Docs now state the Cloudflare/nginx deployment requirements and the domain risks (DNS
  hijack, domain expiry, TLS termination at Cloudflare, key revocation after a server move).
  **Keys that were used with beta.3 travelled in cleartext: revoke and reissue them.**
- **Token refresh fix (#12):** `POST /api/user/auth/refresh` returned 403 `AUTH_ORIGIN_FORBIDDEN` on the production
  server because no Origin header was sent. Proxied state-changing requests (non-GET/HEAD) now carry the pinned server
  origin, never a renderer-supplied value; Referer and Host are still not forwarded.
- **Server compatibility (#13):** server `v1.0.0-rc.47` is marked as tested (manual live verification on 2026-10-28:
  status check, login, self/token/model reads, chat streaming and non-streaming, refresh), so the "untested server"
  warning no longer shows for it. The vendored web snapshot and the minimum server stay at rc.46.
- **Origin guard hardening (#15):** official builds now also reject `https://[::]` (the IPv6 unspecified address, which
  reaches the local host on most stacks) and its IPv4-mapped forms.
- **Docs (#14):** the v0.1.0-beta.3 release notes in the repository were filled in with the real commit, run and
  SHA-256 values.

### Known limitations

- Server `v1.0.0-rc.48` and newer show as "untested". OAuth, passkey, Turnstile and payment flows are not covered by the live verification.
- L3 (paid) connectivity tests are disabled; the real shop and payment flows are unverified.
- Windows file ACLs and upgrade/uninstall paths on real machines are unverified.
- The static bundle scan (check-asar) does not yet catch some obfuscated env/URL forms; runtime origin pinning still applies.
- Unsigned/ad-hoc builds, no auto-update, no Linux packages. Settings may change incompatibly before 1.0.

## 中文

**这是供测试使用的预发布（beta）版本，请勿用于生产环境。**

### 相对 v0.1.0-beta.3 的变化

- **HTTPS 服务器（#11）：** 构建时固定的 origin 现为 `https://flowpier.top`（无端口）。beta.3 适用的 D-17 明文 HTTP
  例外已结束。官方构建守卫重新只接受不带路径的 `https:` origin，拒绝 `http:`、`.invalid` 占位符、路径、userinfo、
  显式默认端口、末尾带点的主机名，以及（官方构建中的）回环主机。文档补充了 Cloudflare/nginx 的部署要求和域名风险
  （DNS 劫持、域名过期、Cloudflare 终止 TLS、服务器迁移后的 key 吊销）。
  **beta.3 使用过的 key 曾以明文传输，请吊销并重新签发。**
- **令牌刷新修复（#12）：** 在生产服务器上，`POST /api/user/auth/refresh` 因未发送 Origin 头而返回 403
  `AUTH_ORIGIN_FORBIDDEN`。现在经代理发出的有状态请求（非 GET/HEAD）会带上固定的服务器 origin，绝不使用渲染进程
  提供的值；仍不转发 Referer 和 Host。
- **服务器兼容性（#13）：** 服务器 `v1.0.0-rc.47` 已标记为“已测试”（2026-10-28 人工实测：状态检查、登录、
  self/token/模型读取、流式与非流式对话、刷新），因此不再显示“未测试服务器”警告。内置的 web 快照和最低服务器版本仍为 rc.46。
- **Origin 守卫加固（#15）：** 官方构建现在还会拒绝 `https://[::]`（IPv6 未指定地址，在大多数协议栈上会连到本机）
  及其 IPv4 映射形式。
- **文档（#14）：** 仓库中的 v0.1.0-beta.3 发布说明已补全真实的提交、运行和 SHA-256 值。
